# Архитектура проекта (быстрый контекст)

Цель файла — за 1–2 минуты понять **где что лежит** и **куда лезть** при правках (UI/API/БД/агент/отчёты).

---

## Репозиторий (корень)

- **`GETTING_STARTED.md`**: единственный запуск (Docker). **`README.md`**: кратко. Подробности — `docs/`. **`update.sh`**: единственное обновление.
- **`run.py`**: uvicorn из корня (Docker entrypoint и e2e).
- **`package.json`**: `npm run docker:*`, тесты, сборка UI.
- **`package-lock.json`**: lockfile корневых dev-зависимостей.
- **`pyproject.toml`**: pytest (pythonpath=backend).
- **`playwright.config.ts`**: e2e (Playwright).
- **`CHANGELOG.md`**: история изменений.
- **`docs/ui-conventions.md`**: соглашения панели (PageHeader, AppFold/AppModal/StatusPill, a11y).

Папки:

- **`backend/`**: FastAPI + **PostgreSQL** + SQLAlchemy (async).
- **`frontend/`**: React + TypeScript + Vite + Tailwind.
- **`agent/`**: агент инвентаризации (Windows, PowerShell/опционально Python), отправка на API.
- **`e2e/`**: e2e-тесты Playwright.
- **`scripts/`**: `ensure_postgres.py`, миграции SQLite→PostgreSQL и утилиты.
- **`node_modules/`** и **`frontend/node_modules/`**: генерируются `npm install`, **не** источник архитектуры.

## Backend (`backend/`)

### Вход и запуск

- **`backend/open_firewall_port.bat`**: открыть входящий порт в Windows Firewall (для LAN-агентов).
- **`backend/requirements.txt`**: python-зависимости (FastAPI/SQLAlchemy/ldap3/fpdf2 и т.д.; pytest в том же файле).
- **`backend/.env.example`**: шаблон настроек.
- **`backend/.env`**: локальные секреты (пароли/токены) — **не коммитить**.

### Приложение (`backend/app/`)

- **`backend/app/main.py`**: сборка FastAPI-приложения.
  - подключает роутеры, CSRF, rate limiting (slowapi),
  - миграции PostgreSQL при старте (`migrations.py`),
  - в production раздаёт `frontend/dist` как SPA (fallback на `index.html`).
- **`backend/app/database.py`**: async SQLAlchemy — три engine (inventory, diagrams, warehouse; обычно одна БД PostgreSQL).
- **`backend/app/models.py`**: ORM-модели БД (Users, Computers, Service Requests, Templates, Tags и т.д.).
- **`backend/app/schemas.py`**: Pydantic-схемы (DTO) для API.
- **`backend/app/config.py`**: `settings` из `.env` (pydantic-settings).
- **`backend/app/auth.py`**: логин/проверка пароля, сессии/куки, хеширование.
- **`backend/app/ldap_config.py`** и **`backend/app/ldap_auth.py`**: LDAP-конфиг и LDAP-аутентификация/синхронизация.

### Роутеры (`backend/app/routers/`)

Эти файлы — “контроллеры” API (эндпоинты + бизнес-логика):

- **`auth.py`**: вход/выход/`/auth/me`.
- **`users.py`**: управление пользователями + админские LDAP-операции.
- **`settings.py`**: настройки (например LDAP-конфиг).
- **`computers.py`**: ПК: список/детали/редактирование/история/экспорт.
- **`tags.py`**: теги (справочник, CRUD).
- **`dashboard.py`**: агрегаты для дашборда (сводные метрики, топы/распределения).
- **`agent.py`**: приём инвентаризации от агента (`POST /api/v1/agent/inventory`).
- **`agent_tokens.py`**: выпуск/отзыв токенов агентов.
- **`service_requests.py`**: заявки (GLPI CSV, PDF, шаблоны).
- **`diagrams.py`**: карта здания, WebSocket.
- **`warehouse.py`**, **`printers.py`**, **`network.py`**, **`wikirag.py`**, **`database_backup.py`**: склад, SNMP-принтеры, сеть, база знаний, бэкап БД.
- **`server_audit.py`**, **`llm_cluster.py`**: аудит серверов / LLM cluster API (UI — `/server-audit`).

## Frontend (`frontend/`)

### Сборка/инструменты

- **`frontend/package.json`**: зависимости UI (React/Router/Chart.js) и скрипты (`dev`, `build`, `test`).
- **`frontend/vite.config.ts`**: Vite-конфиг (в т.ч. прокси `/api` в dev).
- **`frontend/index.html`**: html-шаблон.
- **`frontend/tsconfig*.json`**: TypeScript-конфиг.
- **`frontend/eslint.config.js`**: ESLint.
- **`frontend/README.md`**: заметки по фронту.

### Исходники (`frontend/src/`)

Базовые entrypoints:

- **`frontend/src/main.tsx`**: монтирование React-приложения.
- **`frontend/src/App.tsx`**: маршрутизация (React Router) + охрана роутов (Protected). Legacy `/llm-cluster*` → `/server-audit`; `/knowledge-base` → `/knowledge-base/wikirag`.
- **`frontend/src/AuthContext.tsx`**: контекст авторизации (`me`, `login`, `logout`, user state).
- **`frontend/src/api.ts`**: единая точка API-клиента (fetch, таймауты, типы DTO).
- **`frontend/src/ErrorBoundary.tsx`**: перехват ошибок UI.
- **`frontend/src/index.css`** / **`frontend/src/App.css`**: стили.

Навигация и UI-kit:

- **`frontend/src/components/layout/navConfig.ts`**: **источник правды** для сайдбара/меню (пути, секции, роли).
- **`frontend/src/components/PageHeader.tsx`**: content-first chrome (`h1` sr-only, опциональный muted subtitle, actions).
- **`frontend/src/components/ui/`**: **`AppFold`**, **`AppModal`**, **`StatusPill`** — общие fold/modal/status паттерны (см. `docs/ui-conventions.md`).
- **`frontend/src/components/icons.tsx`**: набор иконок.

Pages (страницы/крупные модули):

- **`Layout.tsx`**: общий layout; читает nav из `navConfig`.
- **`LoginPage.tsx`**, **`DashboardPage.tsx`**, **`ComputersPage.tsx`**, **`SoftwarePage.tsx`**.
- **`ServerAuditPage.tsx`** (+ Actions/Charts/Manage/Session): аудит серверов / LLM cluster UI.
- **`PrintersPage.tsx`**, **`NetworkPage.tsx`**, **`NetworkMapPage.tsx`** (+ `pages/network-map/*`).
- **`WarehousePage.tsx`**: склад.
- **`ServiceRequestsPage.tsx`**: заявки (база/шаблоны/статистика по роуту).
- **`WikiRagPage.tsx`**: wiki / assistant (`/knowledge-base/wikirag`).
- **`KnowledgeSitemapPage.tsx`**, **`GuidePage.tsx`**, **`NotesPage.tsx`**, **`KnowledgeZabbixPage.tsx`**.
- **`UsersPage.tsx`**, settings/* (LDAP, tags, categories, Bitrix24, Zabbix, database, GLPI, LLM, agent-tokens/bundle, WoL, HTTPS).

Types:

- **`frontend/src/types/vendor.d.ts`**: временные декларации модулей (например для chart-библиотек), чтобы TS не ругался.

## Примечания по “источникам правды”

- **Меню/роли навигации**: `frontend/src/components/layout/navConfig.ts`.
- **Данные и формат дат “как в CSV” для заявок**: ориентир `glpi.csv` + логика импорта/вывода в `service_requests.py` и форматирование в `ServiceRequestsPage.tsx`.
- **Прод-режим “один порт”**: фронт собирается в `frontend/dist`, а бэкенд из `backend/app/main.py` начинает раздавать SPA.
