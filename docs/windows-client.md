# Клиент сотрудника (Windows 10 и 11)

`Corax.exe` — окно на компьютере сотрудника. В нём оставляют заявку, смотрят телефонный справочник и запускают уже установленный агент инвентаризации. Само окно железо не собирает: почту, пароли браузера и файлы оно не читает.

Скачивается из панели: **Настройки → Сборка агента → Клиент для сотрудников**. Панель вписывает в файл адрес сервера. Отдельный токен инвентаризации в этот EXE не кладётся. Заявка принимается, если этот компьютер недавно присылал инвентарь, либо если в настройках окна указан ключ обработчика заявок.

Нужен Windows 10 или 11, 64-bit. Сборка тоже только на Windows: в Docker компилятора .NET нет, образ только подставляет готовый шаблон.

## Что поставить

1. [.NET SDK 8](https://dotnet.microsoft.com/download/dotnet/8.0) (именно SDK, не только runtime).
2. Проверка:

```powershell
dotnet --version
```

Должна быть ветка 8 (`8.0.x`).

## Как собрать

Из корня репозитория:

```powershell
cd agent\windows-client
powershell -ExecutionPolicy Bypass -File .\Build-Icon.ps1
dotnet publish -c Release
```

Готовый файл:

```text
agent\windows-client\bin\Release\net8.0-windows\win-x64\publish\Corax.exe
```

Это один self-contained EXE под win-x64: внутри runtime, отдельный .NET на компьютеры ставить не нужно. Первый запуск — установщик. Дальше то же окно заявок.

Иконка необязательна. Если `Assets\corax.ico` нет, проект собирается без неё. `Build-Icon.ps1` рисует знак C и кладёт `Assets\corax.ico`.

## Куда положить шаблон

Панель не компилирует клиент и не переписывает файл. Кнопка отдаёт этот EXE как есть: `Corax.exe`. Первый запуск — установщик, в нём сервер, порт и токен.

Скопируйте опубликованный файл сюда, **под этим именем**:

```text
agent\windows-client\prebuilt\Corax.template.exe
```

Дальше пересоберите образ, чтобы файл попал внутрь:

```text
docker compose build
```

В `Dockerfile` копируется только каталог `agent/windows-client/prebuilt`. Пока шаблона нет, кнопка в панели отвечает 404 и текстом отсылает к этой странице.

Проверка слота без панели (из корня репозитория, нужен Python):

```powershell
python -c "from pathlib import Path; p=Path('agent/windows-client/prebuilt/Corax.template.exe'); print(p.is_file(), p.stat().st_size if p.is_file() else 0)"
```

`BEGIN True` — шаблон годится.

## Как проверить до шаблона

Рядом с программой или в `%LocalAppData%\CORAX\Client\client.json`:

```json
{
  "serverUrl": "http://192.168.1.10:3000",
  "handlerSecret": "",
  "dark": true,
  "autostart": false
}
```

Адрес — LAN-IP панели, не `127.0.0.1` с чужого компьютера. Локальный файл перекрывает адрес, вшитый в EXE.

Запуск исходников (ставится, если EXE запущен не из каталога установки):

```powershell
cd agent\windows-client
dotnet run -c Release -- --app
```

`--app` сразу открывает окно. `--setup` снова показывает установку.

Установленная копия лежит в `%LocalAppData%\CORAX\Client\Corax.exe`. Ярлык на рабочем столе и в меню «Пуск». Автозапуск — значение `Corax` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Крестик прячет окно в трей, выход — из меню трея.

## Что делает окно

- **Заявки** — тема и описание уходят на `POST /api/v1/ticket-handler/intake`. Имя сотрудника панель берёт сама: с последнего отчёта агента или из LDAP. Окно не присылает имя в заголовке.
- **Справочник** — `GET /api/v1/ticket-handler/public/directory`. Только активные люди из LDAP и учётки с ролью «справочник». Телефон подтягивается из `telephoneNumber` или `mobile` при синхронизации LDAP.
- **Этот компьютер** — имя ПК, текущий вход Windows и IPv4. Кнопка инвентаризации запускает `CORAX-Agent.exe` из `%ProgramData%\CORAX\Agent` или `%LocalAppData%\CORAX\Agent`, если агент уже стоит.
- **Настройки** — адрес панели, ключ обработчика, тёмная тема, автозапуск.

Первый запуск скачанного файла — короткая установка: копия в профиль, ярлыки, затем само окно.
