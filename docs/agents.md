# Агенты CORAX

С панели скачиваются два пакета:

- **Windows** — ZIP с `CORAX-Agent.exe`. Запуск ставит агента в `%ProgramData%\CORAX\Agent`, показывает окно установки и оставляет иконку в трее.
- **Linux** — ZIP со bash-скриптами. Каталог `/opt/corax-agent`, не `/opt/corax`.

Токен в EXE не вшит. Рядом лежит `agent.json` (адрес сервера) и одноразовый `agent.provision.json`. После первого запуска Windows прячет токен через DPAPI и стирает файл выдачи. На сервере хранится только HMAC.

## Сбор

Агент сам инвентаризацию не шлёт по таймеру пользователя. Панель решает, когда нужен отчёт:

- **Собрать сейчас** — все ПК, либо **Запросить отчёт** у одного компьютера.
- Либо каждый день / раз в неделю в указанное время.

Трей на вошедшем в систему ПК спрашивает сервер каждые 15 секунд и молча отправляет отчёт, если панель попросила. Задача планировщика «CORAX Agent» делает то же раз в минуту, в том числе когда никто не вошёл. Окно пользователю при этом не показывается.

Двойной щелчок по иконке открывает окно «Система инвентаризации» и адрес сервера.

## Windows

1. Настройки → Сборка агента. Адрес — LAN-IP панели, не `127.0.0.1` и не `172.x` Docker.
2. Скачайте ZIP, на ПК запустите `CORAX-Agent.exe` от администратора (нужно, чтобы создать задачу).
3. После первого отчёта на рабочем столе появляется ярлык «Оставить заявку»: `http://LAN-IP:3000/h#pc=ИМЯ-ПК`.

Повторная сборка создаёт новый токен. Старый действует, пока его не отзовут в «Токены агентов».

## Linux

Распакуйте ZIP в `/opt/corax-agent`. URL и токен — в `agent_env.sh`, его не затирайте при обновлении скриптов (`update_scripts.sh`). Расписание — cron или unit из `systemd/`.
