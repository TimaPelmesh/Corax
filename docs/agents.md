# Агенты CORAX

С панели скачивается агент в трее:

- **Windows** — один файл `CORAX-Agent.exe` с синей кнопки. Ставится в `%ProgramData%\CORAX\Agent`, висит в трее, шлёт инвентарь после одобрения в панели и кладёт ярлык «Оставить заявку» на `/h`.
- **Linux** — ZIP со bash-скриптами. Каталог `/opt/corax-agent`, не `/opt/corax`.

Заявки сотрудник оставляет в веб-форме `/h`, отдельный клиентский EXE не нужен.

На сервере хранится только HMAC токена.

## Сбор

Первый отчёт уходит сразу при запуске EXE.

Дальше панель решает, когда нужен следующий:

- **Собрать сейчас** — все ПК, либо **Запросить отчёт** у одного компьютера.
- Либо каждый день / раз в неделю в указанное время.

Трей на вошедшем в систему ПК спрашивает сервер каждые 15 секунд и молча отправляет отчёт, если панель попросила. Если EXE запущен от администратора, задача планировщика «CORAX Agent» делает то же раз в минуту, в том числе когда никто не вошёл.

## Windows

1. Настройки → Сборка агента. Адрес — LAN-IP панели, не `127.0.0.1` и не `172.x` Docker.
2. Скачайте `CORAX-Agent.exe`. Положите на шару или на ПК и запустите.
3. После первого отчёта на рабочем столе появляется ярлык «Оставить заявку»: `http://LAN-IP:3000/h#pc=ИМЯ-ПК`.

Повторная сборка создаёт новый токен. Старый действует, пока его не отзовут в «Токены агентов».

## Linux

Один токен на все серверы. Каталог `/opt/corax-agent`, не `/opt/corax`. Панель отличает машины по `hostname -s`.

Сборка агента → Linux → «Команда установки»: одна строка `sudo python3 -c '...'` на сервере. Она скачивает скрипты, пишет токен и поднимает службу. «Поставить по SSH» делает то же с панели: хост, пользователь, пароль. Пароль не сохраняется, на сервер уходит только установщик. Интервал и действия после запуска — во вкладке «Аудит серверов». ZIP остаётся запасным путём.

Первый отчёт сам создаёт строку во вкладке «Аудит серверов». Инвентарь (ОС, диски, ПО) по-прежнему в «Компьютеры».

Управление на карточке хоста — не shell: проверка nginx и sshd, статус, перезапуск службы из фиксированного списка, чтение файла из списка, запись только в каталог конфигов. Наблюдатель задания не видит.

`update_scripts.sh` не затирает `agent_env.sh`. Lock обновления — `.corax-update.lock` в каталоге агента, не в `/tmp`.
